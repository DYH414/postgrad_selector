## 1. 项目概述

### 1.1 项目定位

408 考研择校决策平台是一个面向考研学生的智能择校推荐系统。用户输入预估分数、目标地区、择校偏好后，系统通过 **"数据库筛选 + 规则引擎 + AI 分析 + 多重校验"** 四阶段流水线自动生成一份包含冲刺、稳妥、保底三档的择校草稿，并支持 AI 对话式交互对草稿进行调整优化。

## 2. 系统架构

### 2.1 模块架构

```
pom.xml (root, packaging=pom)
├── ruoyi-admin          — 入口模块（RuoYiApplication）、Controller 层、全局配置
├── ruoyi-framework      — 安全框架（JWT 过滤器、权限服务、限流切面）、线程池配置
├── ruoyi-postgrad       — 核心业务模块：择校推荐、AI 对话、数据管理
├── ruoyi-system         — 系统管理域（用户、角色、菜单、部门、公告）
├── ruoyi-common         — 共享层：BaseEntity、AjaxResult、注解（@Anonymous/@RateLimiter）、工具类
├── ruoyi-generator      — 代码生成器（Velocity 模板 → 完整 CRUD 栈）
└── ruoyi-quartz         — 定时任务管理（内存调度器，无 DB 持久化）
```

**三层架构约定**:

```
Controller (ruoyi-admin) → IService/ServiceImpl (ruoyi-postgrad) → Mapper (ruoyi-postgrad) → Mapper XML
```

- Controller：仅接收请求、校验参数、返回 `AjaxResult` / `SseEmitter`，**严禁业务逻辑**
- Service：所有业务逻辑、计算、校验、编排
- Mapper：数据访问 + MyBatis XML 中的所有 SQL

### 2.2 请求流程

```
客户端 (浏览器/App)
  │
  ├─ /app/*（匿名端点：登录、注册、验证码、SSE streamToken 订阅）
  │   └─ AppAuthenticationFilter → AppTokenService → SecurityContextHolder
  │
  ├─ 其他 API（需认证）
  │   └─ JwtAuthenticationTokenFilter → 解析 Bearer Token
  │       → Redis 查找 login_tokens:<uuid>
  │       → 设置 SecurityContextHolder
  │
  ├─ @PreAuthorize("@ss.hasPermi('module:action')")
  │   └─ PermissionService.hasPermi() → 检查用户权限 Set
  │       （admin 角色持有 "*:*:*" 通配权限）
  │
  └─ Controller → Service → Mapper → MyBatis XML → MySQL
                              │
                              └─ Redis (缓存草稿/候选池/对话状态)
```

### 2.3 认证流程

1. **JWT 过滤器**: `JwtAuthenticationTokenFilter` 对每个请求提取 `Authorization: Bearer <token>`，解析 JWT，从 Redis key `login_tokens:<uuid>` 查找 `LoginUser`，设置 `SecurityContextHolder`
2. **权限校验**: `@PreAuthorize("@ss.hasPermi('module:action')")` 通过 `PermissionService.hasPermi()` 检查权限
3. **匿名放行**: `@Anonymous` 注解标记的端点由 `PermitAllUrlProperties` 在启动时扫描收集，自动加入白名单
4. **App 端认证**: `/app/*` 路径经过 `AppAuthenticationFilter`，使用 `AppTokenService` 验证 token
5. **会话策略**: STATELESS，CSRF 禁用，密码编码器为 BCrypt
6. **线程传递**: `SecurityContextHolder.MODE_INHERITABLETHREADLOCAL`（确保异步线程可获取认证信息）

## 3. 核心业务流程

### 3.1 候选池构建（四阶段）

整体流程由 `DraftServiceImpl.generateDraft()` 编排，通过 SSE 向前端推送实时进度。

```
用户触发生成
  │
  ├─ 阶段1: DB 12 表 JOIN 筛选（RecommendationMapper.selectCandidates）
  │   ├─ 从 program → college → school 联查
  │   ├─ LEFT JOIN admission_score / admission_plan / admission_result（最新年份）
  │   ├─ LEFT JOIN program_subject + subject（科目组合匹配）
  │   ├─ LEFT JOIN program_year_data_quality（数据质量评级）
  │   ├─ LEFT JOIN data_source（来源追溯）
  │   ├─ 条件：is_408=1, status=active, study_mode=full_time
  │   ├─ 分数范围：estimatedScore ± 30
  │   ├─ 地区过滤：province/city IN (targetRegions)
  │   └─ 两套科目组合去重合并
  │
  ├─ 阶段2: 规则引擎筛选 + classifyTier（CandidatePoolServiceImpl）
  │   ├─ RowMap → SchoolFact 转换（计算 gap、quotaRisk、canBeSafe）
  │   ├─ classifyTier 分档（唯一真相来源）:
  │   │   ├─ reach:  gap ∈ [-15, 5]
  │   │   ├─ steady: gap ∈ [6, 14] 或 gap≥15 但 canBeSafe=false
  │   │   ├─ safe:   gap ≥ 15 且 canBeSafe=true
  │   │   └─ null:   gap < -15 → 排除
  │   └─ 排除数据完整度为 C 的候选
  │
  ├─ 阶段3: policyScore 综合排序 + diversityTrim（CandidateWorkspaceServiceImpl）
  │   ├─ policyScore 权重：
  │   │   ├─ 数据完整度: A=30 / B=20 / C=10
  │   │   ├─ 名额风险: normal=30 / medium=20 / high+very_high=10
  │   │   ├─ 学校层次: 985=25 / 211=18 / 其他=10
  │   │   └─ gap 适配度: max(0, 15 - |gap - idealGap|)
  │   ├─ 偏好加权（schoolTierPref 三种策略）:
  │   │   ├─ school_tier_priority: 学校层次分乘以 1.36 倍
  │   │   ├─ safe_admission_priority: gap 额外加分 + 名额/数据奖励
  │   │   └─ developed_region_priority: 发达城市 +14
  │   ├─ diversityTrim: 同学校只保留得分最高的一个专业方向
  │   └─ 每档截断至 PER_TIER_LIMIT=30（给 AI 选择留充足空间）
  │
  └─ 阶段4: AI 精选（AiSelectorServiceImpl → SelectionValidator 五层校验）
      └─ 每档从 Workspace 候选中对 AI 调用，选出最优
```

**目标数量（Draft 最终产出）**:
- 冲刺档(reach): 3 所
- 稳妥档(steady): 4 所
- 保底档(safe): 3 所

### 3.2 AI 选择与校验

#### 3.2.1 AI Prompt 设计

每档使用独立的提示词模板（`prompts/v2/select-reach.txt` / `select-steady.txt` / `select-safe.txt`），接受**事实卡格式**的候选列表，要求 AI 输出 JSON 数组：

```
ID:123 | XX大学 | 计算机技术 | 985 | 北京 | 均分345 | 差距+10 | 招生15
```

注意：事实卡中**只输出原始数据字段**，不输出后端预判标签（如"名额充裕""可以保底"等），让 AI 从原始数据自行推理。

#### 3.2.2 AI 返回 JSON 结构

```json
[
  {
    "programId": 123,
    "reason": "录取均分345，与你的预估分355差距合理...",
    "risks": ["计算机技术方向竞争激烈", "招生名额偏少"],
    "pros": ["985院校层次高", "录取数据完整"],
    "cons": ["地处偏远", "复试信息不透明"]
  }
]
```

#### 3.2.3 五层校验（SelectionValidator）

```
AI 返回 SelectedItem[]
  │
  ├─ L1: 池外检测 — programId 不在候选池 → 拦截（标记为"AI 幻觉"）
  ├─ L2: 去重 — 同一 programId 出现多次 → 保留首次，其余拦截
  ├─ L3: 数据不足 — dataCompleteness = "C" → 拦截（标记"不具备作为主推荐条件"）
  ├─ L4: 档位上限裁剪 — 超过 limit → 溢出拦截
  │     reach ≤ 3, steady ≤ 4, safe ≤ 3
  └─ L5: 通过 → 合并到 TierCandidates
```

#### 3.2.4 AI 降级链（Fallback Chain）

```
1. 候选为空 → 返回空结果
2. 候选数 ≤ 档位上限 → 请 AI 为全部候选生成 opinion（不要求取舍）
   └─ AI 失败 → selectAll: 全部选中，使用通用理由
3. 调用 LLM → 正常流程
   └─ LLM 异常 → selectAll: 取 top N
   └─ LLM 返回空 → selectAll: 取 top N
   └─ JSON 解析失败 → selectAll: 取 top N
4. 超时 (90s) → fallbackTierResult: 直接取候选池排序后的前 N 所
```

**关键设计**: 降级后的学校标记 `fallback=true`，前端显示"系统自动选择"标签，无法展示 AI 分析理由。

### 3.3 Agent 工具调用

系统使用 LangChain4j 的 `@Tool` 注解 + `AiServices` 构建工具增强的对话 Agent。

#### 3.3.1 12 个工具

**只读工具（V2ChatTools — 6 个）**:

| 工具名 | 功能 | 回退策略 |
|--------|------|----------|
| `getProgramDetail` | 查询单校完整数据（含近3年趋势） | Workspace → Pool → DB |
| `searchPrograms` | 按关键词/档位/地区搜索 | Workspace → Pool → DB（全国范围） |
| `comparePrograms` | 两校并排对比 | Pool snapshot |
| `getRefillCandidates` | 获取指定档位填充候选 | Workspace |
| `getDraftContext` | 查看当前草稿状态 | Redis Draft |

**写操作工具（V2DraftActionTools — 7 个）**:

| 工具名 | 功能 |
|--------|------|
| `removeDraftCandidate` | 移除单校（自动触发 refill 策略） |
| `batchRemoveDraftCandidates` | 批量移除多校 |
| `addDraftCandidate` | 添加学校到草稿（Workspace → DB 回退） |
| `confirmRefillCandidate` | 确认填充候选 |
| `replaceDraftCandidate` | 替换草稿中的学校 |
| `batchReplaceDraftCandidates` | 批量替换 |
| `fillTier` | 一键填满指定档位 |

#### 3.3.2 Write 互斥机制

每次 AI 对话中的单轮只能执行**一个**写操作（`fillTier` / `batchRemove` 各自算一个）。由 `V2ChatToolContext.writeExecuted()` 标记，工具方法在执行前检查：

```java
if (V2ChatToolContext.writeExecuted())
    return error("write_already_executed", "Write already executed this turn.");
```

#### 3.3.3 ThreadLocal 上下文管理

`V2ChatToolContext` 使用 `ThreadLocal<Context>` 持有当前对话的 userId、Redis 模板、数据库 Mapper。初始化模式：

```java
V2ChatToolContext.init(userId, redisTemplate, recommendationMapper);
try {
    assistant.chat(message).start();
} finally {
    V2ChatToolContext.clear();
}
```

提供 `callWith(Context, Supplier)` 方法在线程间传递上下文（当 LangChain4j 工具调用线程不同于发起线程时使用）。

### 3.4 对话记忆系统

#### 3.4.1 双存储架构

| 存储 | 用途 | Key / Table | TTL |
|------|------|-------------|-----|
| **Redis** | 热对话历史、系统提示词 | `ai:v2:chat:{userId}` / `ai:v2:chat:msg:{userId}` | 30分钟 |
| **MySQL** | 持久化消息归档 | `ai_chat_conversation` / `ai_chat_message` | 永久 |

#### 3.4.2 每轮系统提示词注入

每次对话轮次开始前，**重新构建**系统提示词，确保草稿调整后的最新档位和操作 ID 注入到上下文中：

```
系统提示词 = prompt模板 + {profileContext} + {draftContext}
```

- `profileContext`: 用户预估分数、目标地区、择校偏好
- `draftContext`: 当前草稿的档位组成、学校名称、programId、AI 分析理由

#### 3.4.3 滑动窗口记忆

- 使用 LangChain4j `MessageWindowChatMemory.withMaxMessages(20)` 限制上下文大小
- 超出窗口的旧消息不传入 LLM，避免 token 超限

#### 3.4.4 草稿生成时的对话终结

新草稿生成时，自动终结旧对话：
```java
aiChatMapper.finalizeActiveConversations(userId);
redisTemplate.delete("ai:v2:chat:msg:" + userId);
redisTemplate.delete("ai:v2:chat:system:" + userId);
```

### 4.2 12 表 JOIN 查询（RecommendationMapper.selectCandidates）

核心查询 SQL 联查 12 张表：

```
program
  JOIN college         ON program.college_id = college.id
  JOIN school          ON college.school_id = school.id
  LEFT JOIN (program_subject + subject 聚合子查询) ON program.id
  LEFT JOIN admission_score（最新年份） ON program.id
  LEFT JOIN admission_plan（同年份）      ON program.id
  LEFT JOIN admission_result（同年份）    ON program.id
  LEFT JOIN program_year_data_quality     ON program.id + year
  LEFT JOIN data_source（admission_score 来源）
  LEFT JOIN data_source（admission_plan 来源）
  LEFT JOIN data_source（admission_result 来源）
```

动态数据完整度计算（SQL 内联）：

```sql
CASE
    WHEN score_line IS NOT NULL AND min/max/avg_admitted_score IS NOT NULL
         AND (total_plan IS NOT NULL OR unified_exam_quota IS NOT NULL OR admitted_count IS NOT NULL)
    THEN 'A'
    WHEN score_line IS NOT NULL AND (avg_admitted_score IS NOT NULL OR ...)
    THEN 'B'
    WHEN completeness_level IS NOT NULL THEN completeness_level
    ELSE 'C'
END AS dataCompleteness
```

## 5. 性能优化

### 5.1 CompletableFuture 并行 AI 调用

三档 AI 选择互不依赖，使用 `CompletableFuture.supplyAsync()` 并行提交到线程池，将串行 60s 的 AI 调用缩短为 ~20s：

```java
List<CompletableFuture<TierResult>> futures = new ArrayList<>(3);
for (WorkspaceTierVO wsTier : wsTiers) {
    CompletableFuture<TierResult> future = CompletableFuture
        .supplyAsync(() -> aiSelectorService.select(...), threadPoolTaskExecutor)
        .orTimeout(90, TimeUnit.SECONDS)     // 单档超时 90s
        .exceptionally(ex -> fallbackTierResult(...));  // 异常兜底
    futures.add(future);
}
// 逐档收集结果（不阻塞其他档），逐档持久化（支持刷新恢复）
for (CompletableFuture<TierResult> future : futures) {
    TierResult tr = future.join();
    saveDraft(userId, partial);
    callback.onTierComplete(tr.level, ...);
}
```

### 5.2 ThreadPoolTaskExecutor 配置

```java
// 核心线程数: 50
// 最大线程数: 200
// 队列容量: 1000
```

## 6. 安全与可靠性

### 6.1 JWT 认证

```yaml
token:
  header: Authorization
```

- BCrypt 密码编码器

### 6.3 限流

通过 `@RateLimiter` 注解 + AOP 切面实现：

```java

```

- 基于 Redis Lua 脚本原子计数
- 支持全局限流（DEFAULT）和 IP 限流（IP）
- 超出限制抛出 `ServiceException("访问过于频繁，请稍候再试")`

### 6.4 CORS 配置

通过 `CorsFilter` 在 Security 过滤器链最前端处理跨域请求。

### 6.5 异常处理

全局异常处理器 `GlobalExceptionHandler` 统一处理：
- `ServiceException` → 业务异常消息
- `SecurityException` → "未登录"
- 未捕获异常 → 通用错误消息（**不暴露内部堆栈**）

### 6.6 分布式锁

**草稿生成锁**: 防止重复点击导致多个 LLM 调用并行

```java
// 获取锁（SETNX + TTL）
Boolean locked = redisTemplate.opsForValue()
    .setIfAbsent(lockKey, lockValue, LOCK_TTL);  // TTL=10min，覆盖三档 AI 调用
if (Boolean.FALSE.equals(locked)) {
    callback.onError(new IllegalStateException("已有草稿正在生成，请稍候"));
    return;
}

// 释放锁（Lua 原子校验：仅当 value 匹配时才删除，防止误删他人锁）
redisTemplate.execute(UNLOCK_SCRIPT, Collections.singletonList(lockKey), lockValue);
```

**对话并发锁**: 防止同一用户同时发多条消息导致对话历史覆盖（TTL=60s）。

### 6.7 SSE 安全

SSE 端点 `streamGenerateDraft` 标注 `@Anonymous`（EventSource 不支持自定义 Header），通过 `start` 端点发放的短期 `streamToken` 进行二次鉴权：

```java
                                      @RequestParam String streamToken) {
    if (!draftGenerationTaskService.validateStreamToken(taskId, streamToken)) {
        // 返回错误 SseEmitter
    }
    // 正常流程
}
```
