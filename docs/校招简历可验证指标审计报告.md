## 0. 结论先行

### 当前可写进简历的量化事实

1. **构建 63 条 RAG 开发集。** 这是源码静态数据集的准确数量，不附带未固化的质量分数。

4. **本轮定向测试 71/71 通过。** 其中 17 个覆盖 RAG 评测逻辑与 Tool Runtime，54 个覆盖选择校验、降级、锁和草稿修改边界。这是本地 Mockito/单元/契约测试，不是线上稳定性或并发压测数据。

- `frozen test 20 条`：源码实际为 18 条，不是 20 条。
- `MRR=0.742`、`Hit@K`、`Filter Accuracy=100%`：未找到对应索引版本、模型、运行时间和原始报告；并且当前 Filter/nDCG 实现存在统计口径问题。

- “60s+ -> 15s”、SSE 首结果时间、推荐 P50/P95：没有相同条件的性能实验或原始日志。
- 真实用户数、成本、P99、线上成功率：数据库记录无法区分真实用户与本地测试，且没有成本/端到端耗时持久化。

### RAG 评测需要先修正的事实问题

1. “63 dev + 20 test”与源码不符，当前是 **63 dev + 18 test**。
2. `structuredMetrics` 只合并 `fact + trend = 27`，`general = 12`，`negative = edge = 12`，遗漏 `quality = 12`；因此三段合计 51，而不是 63。
3. 负样例不能用普通 MRR/Hit@K 直接表达“正确拒答”；需要单列：
   - `NoAnswerAccuracy = 正确空召回或拒答数 / no-answer 样本数`
   - `FalsePositiveRate = 有无关召回的 no-answer 样本数 / no-answer 样本数`
4. nDCG 需以每个 rank 的二元/分级 relevance 计算 DCG，并按相同相关文档数计算 IDCG，确保结果在 `[0,1]`。

2. 修复 nDCG，补齐 no-answer accuracy、FPR、citation precision/recall；将 `quality` 纳入分段统计或明确第四段。
3. 在固定 frozen test 上运行 Vector Only 与 Vector + Rerank，输出逐 case 排名和聚合 MRR/Hit@K/平均排名/P50/P95。
4. 固定画像、候选池、模型和并发度，串行/并行各至少 30 次，记录首个 SSE 事件和 `done` 时间，再写 P50/P95 与提升比例。
