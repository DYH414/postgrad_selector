# README 重写设计

## 目标

把根目录 `README.md` 重写为面向开源访问者的项目首页，使读者在三分钟内回答：

1. 这是什么项目，解决什么问题？
2. 它与普通 LLM Demo 有什么区别？
3. 核心架构和技术亮点是什么？
4. 如何在本地启动并完成最小验证？
5. 去哪里阅读详细架构、运维和面试材料？

README 不承担完整技术设计、生产部署手册、开发历史和内部协作规范的职责。

## 目标读者

- 浏览 GitHub 项目的面试官和招聘人员。
- 想运行项目的开发者。
- 想了解 Agent/RAG 工程实现的学习者。

## 信息结构

1. 项目标题、单句定位、在线体验和状态说明。
2. 项目概览：业务规模、适用场景和事实约束原则。
3. 核心亮点：事实约束 Agent、Tool Runtime、安全写协议、版本化 RAG、长任务治理。
4. 系统架构图：规则推荐、Agent Tool、RAG 和可观测性的主要关系。
5. 产品能力：用户端与管理端的精简清单。
6. 技术栈：只列当前源码直接使用的主要组件，不维护易漂移的细碎版本号。
7. 快速开始：依赖、数据库、环境变量、Qdrant、后端和两个前端。
8. 最小验收：健康检查、RAG 索引和检索验证。
9. 项目结构：仅说明主要模块。
10. 测试与评测：说明测试命令、frozen 数据集和指标边界。
11. 文档导航：链接到权威长文档。
12. 项目边界、License 和致谢。

## 删除或迁移

- 删除 README 中详细 Tool 时序图、五层校验展开和实现级算法说明。
- 删除重复的本地、Nginx 和云服务器部署教程；复杂部署链接到运维文档。
- 删除服务器路径、面板信息和内部环境细节。
- 删除“截图待补充”等占位内容；没有可提交截图时不保留截图章节。
- 删除内部 Controller/Service/Mapper 编码规范，保留在 `CLAUDE.md` 或贡献指南。
- 删除过期 Tool 清单、易漂移版本号和未经严格验证的性能宣传。
- 不在 README 展开面试话术、历史设计方案或开发过程。

## 内容边界

- 可以说明当前源码存在 16 个 Tool，但不逐项展开全部 Schema。
- 可以说明本地历史全量索引达到 3,581 份逻辑文档和 21,461 个 Chunk，但必须标明批次口径。
- 可以展示 frozen 评测结果，但必须同时写样本量和 Rerank 延迟代价。
- “60s+ 到约 15s”不作为 README 核心指标，避免把开发观察值表述为稳定基准。
- Alias 使用“平滑切换活动索引”，不写“经过压测的零停机”。
- 当前链路是 Dense Vector + Metadata Filter + Rerank，不称为 Hybrid Search。

## 快速开始原则

- 命令必须可复制。
- 环境变量只展示名称和占位值，不出现真实密钥、账号或服务器信息。
- 区分必需依赖和可选能力。
- 数据库 SQL 顺序必须来自仓库现状；如果无法保证全新环境一键导入，应明确提示使用现有初始化说明。
- RAG 首次使用必须说明需要在管理端创建 Index Run，不能暗示后端启动即自动重建。

## 验收标准

1. README 控制在约 250-350 行，首屏可看到定位、在线地址和核心亮点。
2. 不包含“TODO、待补充、截图待补充”等占位符。
3. 不包含真实密钥、密码、服务器 IP、绝对部署路径。
4. 所有相对文档链接指向存在文件。
5. 模块名、端口、环境变量、Tool 数和 RAG 口径与当前代码一致。
6. `git diff --check` 通过。
7. README 不复制长篇技术文档，而是提供清晰导航。
